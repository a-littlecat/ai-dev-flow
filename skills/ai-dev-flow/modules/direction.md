# 方向：原型、决定卡、基准、流程图

队列奖励"完成项"，看不出整体有没有走对。一个项目按队列推进约三周、合了几百个提交，每项都过了复核和快检，直到拿最终交付物和"人＋通用模型"的结果逐类对照，才发现整体更差。本模块让这类问题早发现，也让用户的注意力放在决定点上。

适用于：用户提了新方向；或者你做的时候碰到第 1、3 节列的情况。任何信任等级都一样。

## 1. 什么算新方向

满足任一条：

- 换路线或核心做法；
- 新增子系统；
- 预计投入 3 天以上，或 10 个队列项以上。

已定方向里照计划做的项、修 bug、普通小功能不算。用户明确说不用原型的，把原话写进队列那一项，直接按第 3 节报卡。

## 2. 先做原型，和基准比

1. **排一项原型**：队列里目标写 `[方向原型 <方向名>] <要验证什么>`，档是看一眼。方向名短、不带方括号，这个方向的项都用同一个名字。
2. **可扔、端到端**：1～3 天，一个 worktree 和分支，从真实输入一直走到最终交付物。不追求整洁，不进快检，不合主干，所以不用独立验证。超过 3 天做不出来，这本身就是结论，停下报。
3. **同口径并排比**：在固定输入上，和基准比质量、成本、用时，出一张能直接看的并排图。比较用的工具是新写的，按 `build.md` 第 3 节先自验。
4. **看结果**：
   - 比过基准，或者差距清楚、又有可信的补法：按第 3 节报决定卡，卡里写 `方向：<方向名>`（有待定的卡，原型超预算不算要停），附并排图和数字，队列这一项写成 `待用户（决定卡 <路径>：<一句>）`。原型分支留着，等用户定。
   - 没比过，也说不出补法：队列这一项写成 `完成（没比过基准：<差在哪>）`，`docs/benchmark.json` 里这个方向的 `state` 改成 `结束`，在汇报里说一句。这是唯一不用用户定就能结束的情况：方向还没开。
5. **用户定了才排正式项**：目标写 `[方向 <方向名>] <做什么>`。原型的代码不直接合，正式项从主干重新做，能用的部分照常走 `build.md`、`verify.md`。

## 3. 方向性选择报决定卡

下面这些一律由用户定，任何信任等级的会话都不能自己定：

- 换路线或核心做法；
- 新增或砍掉子系统；
- 改评分口径或北极星；
- 改上线范围；
- 投入超预算。

普通实现细节照旧自己定，不报卡。拿不准算不算的，先做不依赖它的部分，按这一节报。

**怎么报**：

1. 照 `<skill>/templates/decision-card.md` 写一张卡，放在 `docs/decisions/<YYYY-MM-DD>-<主题>.md`，一页以内。卡里的图用相对路径，文件放进仓库能打开的地方；项目规定数据不入库的，放在 `.agents/` 下。
2. 队列那一项写成 `待用户（决定卡 <路径>：<要定什么，推荐哪个>）`，单独提交，发 `user` 通知。
3. 接着做不依赖这个决定的项。派出去的执行方（子 agent、外部 agent）碰到这些选择不自己定，写进结束报告，由编排会话报卡。

**用户答复后**（`/next #n 选 B`）：把卡的状态改成 `已定（<日期>）`，原话抄进卡的"用户的决定"，再把决定拆成队列项。这张卡是因为方向要停或差距没缩小才报的，同时改 `docs/benchmark.json`，不然下次还会报：

- 继续的：这个方向的 `decided` 写今天，超预算的同时加预算；没有方向的，顶层 `decided` 写今天。
- 放弃的：`state` 写 `结束`，`decided` 写今天，队列里这个方向没做完的项改成 `搁置（方向已放弃）`。
- 原型通过的：`state` 改 `进行中`，`decided` 写今天，写好正式的预算。

## 4. 基准

基准＝同样的输入直接交给当时最强的通用模型或智能体做的结果，含成本和用时。没有它，就看不出几百个提交比"直接问模型"强在哪。

每个推进中的项目在 `docs/benchmark.json` 登记一份，路径都相对仓库：

```json
{
  "northStar": "<最终交付物和基准的差距怎么量，一句话>",
  "baseline": { "model": "<模型或智能体>", "date": "2026-11-08", "input": "<固定输入>", "cost": "<成本>", "minutes": 40, "image": "docs/benchmark/baseline.png" },
  "directions": [ { "name": "<方向名>", "state": "进行中", "started": "2026-11-08", "budgetDays": 14, "budgetQuota": 100, "spentQuota": 0, "decided": "2026-11-08" } ],
  "runs": [ { "date": "2026-11-08", "gap": 0.18, "image": "docs/benchmark/2026-11-08.png", "note": "<一句>" } ]
}
```

- **gap（差距）**：一个数，0 是和基准一样，大于 0 是比基准差，小于等于 0 是比过了。口径写在 `northStar`，量最终交付物，不量中间结果。这就是项目的北极星（`harness.md` 第 2 节第 5 条）。
- **runs**：至少每周量一次，追加一条，`image` 是这次和基准的并排图。图是项目数据、规定不入库的，放在主检出的 `.agents/` 下，路径照写（在 worktree 里跑也找得到）；状态页只读本机文件。
- **状态页**（`daily.ps1`）显示最近一条 run 的 `image`、按周的差距小图和待定的决定卡（`portfolio.md` 第 6 节）。图只认仓库里、真实存在的文件；路径写错的，`direction.ps1` 报出来。
- **baseline**：新模型出来或每月一次，用同样的输入重跑，更新这一段。换了基准差距会跳，在那条 run 的 `note` 里写一句。
- **directions**：每个方向开工时写预算：`budgetDays` 必填，`budgetQuota`、`spentQuota` 用项目自己的单位。原型写 `"state": "原型"`，用户定了改 `进行中`，结束改 `结束`。预算要加、方向要结束，都是用户定（第 3 节）。
- **没有基准可比的项目**（工具库、文档、维护中的项目；价值主要在数据、权限和长期运行的普通网站、业务系统）：用户确认了才写 `{ "notApplicable": "<原因>" }`，基准和流程图都不再要求；问的时候说清两样都免，原话记进队列那一项。

第一次登记是一项看一眼档：`/next` 开场自动加（目标里写"登记基准"）；口径是这项要用户确认的，跑完把并排图给用户看。已经在推进的项目，同时把当前主线登记成一个 `进行中` 的方向并写预算，队列里没做完、属于它的项，目标开头补上 `[方向 <方向名>]`：没有标记，方向要停时拦不住它们。

## 5. 收敛

`scripts/direction.ps1` 判断，`/next` 开场和 `status.ps1` 都跑它，退出 3 表示有要处理的，逐条列出：

```
pwsh -NoProfile -File <skill>/scripts/direction.ps1 -Repo . [-Json]
```

每周取最后一次测量，方向"要停"的条件：

- 差距连续 2 周没缩小（最近三个周点依次没变小，最近一点大于 0）；
- 差距 14 天没量（不量就算没缩小）；
- 预算花完（天数或额度），差距还大于 0。原型超预算不看差距，直接算；有待定决定卡的原型在等用户，不算。

只看 `started` 和 `decided` 之后的测量，用户定过以后重新算，比过基准也只认这之后、基准重跑之后的测量。比过基准以后不再因为没缩小而停，但还是要量。

**方向要停时**（目标开头是 `[方向 <方向名>]`、`[方向原型 <方向名>]` 的项算这个方向的）：

1. 不再领、不再派这个方向的新项。已经派出去的做完，不合并的留着。状态页也不把它们算成可领；已结束的方向同样。
2. 队列最前面加一项 `方向复盘：<方向名>`（已有就不加），档是看一眼：照 `garden.md` 第 2 节看这个方向合进去的东西，再加一条：为什么差距没缩小。
3. 按第 3 节报决定卡：继续（怎么改、加多少预算）、换路线、放弃。用户定之前这个方向不动。
4. 不属于这个方向的项照常做。

项目没有未结束的方向时，差距没缩小照样报：加一项 `方向复盘`，只是没有项要停；看的是顶层 `decided` 和已结束方向的 `decided` 之后的测量。

队列里有 `[方向 X]` 项，`directions` 里 X 却不是进行中的，`status.ps1` 提示：用户定了才排。

## 6. 一页流程图

用户不该靠翻会话过程才知道项目在干什么。每个推进中的项目维护一页 `docs/flow.html`，照 `<skill>/templates/flow.html` 改，白话说明加一张图：

- 从输入到输出几步；
- 每步谁做（模型、程序、人、外部服务）；
- 步骤之间传什么数据；
- 每步怎么量好坏；
- 已知短板。

写给不看代码的人，不写函数名和路径。样式和脚本模板里写好了，不用改：页面把各步画成一条主干，交替向上下分出去，选中哪步才在下面显示它的细节；只用墨色，朱红只给轮到人的步骤；最后一个节点写交出去的东西。状态页里嵌的这页不跑脚本，看到的是同样内容的竖排主干。还没有这页的，`/next` 开场自动加一项（目标里写"流程图"），档是看一眼，写完让用户看。`status.ps1` 也提示，状态页的项目卡上有链接。

**改了步骤，或者改了模型和程序的分工**：同一个提交更新这页，提交前按第 3 节报决定卡请用户确认。只修短板、换说法的直接改。

**周会可选"讲解一步"**：用户点名哪一步，拿真实样例讲 15 分钟（`skills/week/SKILL.md`）。

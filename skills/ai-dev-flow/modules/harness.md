# 给项目搭 harness

项目自带的验证能力是最值钱的资产。没有它，"自走"不成立，项目只能停在 L0，每次合并都要问人。

## 1. 什么时候做

- 第一次进入项目，`AGENTS.md` 里没写 verify 命令。
- 某项改动没法被现有 verify 证明：把补 verify 当作这项改动的一部分。
- 复盘发现某类问题反复漏掉：补一项能抓住它的检查。

只加脚本、样例和文档的部分属于自走档。装软件、改系统或安全设置、加远程属于单向门。

## 2. 最低要求（升到 L1 之前要有）

1. **verify（快）**：一条命令，例如 `scripts/verify` 或 `npm run verify`，包含格式化、类型检查、lint、单测和关键回归，目标 2 分钟内跑完。退出码 0 才算通过，失败时要打出能定位的信息。
2. **verify:full（慢）**：e2e、全平台、真实宿主软件。可以慢，但必须无人值守。慢而且独占资源的，做成队列（第 4 节）。
3. **能操作产品**，按项目类型选：
   - Web：Playwright 脚本，加截图
   - 桌面应用或宿主插件：一个 CLI，负责启动、驱动、抓日志和截图
   - CLI 或数据处理：样例输入 → 期望输出，逐项对比
   - 调模型的功能：固定评测集，一条 `eval` 命令输出分数表和费用
4. **功能地图** `docs/feature-map.md`：每个功能从哪里进入、怎么验证、对应哪些样例，以及**改到哪些区域要跑哪项慢验证**。agent 按这张表决定一个改动要跑哪些检查，不必每次都跑全量。
5. **北极星数字**：一个能看出离目标还有多远的数，例如兼容矩阵里通过的格数、评测集分数、端到端通过率。口径写死在 `AGENTS.md`，每次汇报和摘要都用同一个口径。
6. **`AGENTS.md` 改成目录**，100 行以内：verify 命令、信任等级、北极星口径、单向门补充、预算、禁止项、各文档入口。长内容移到 `docs/`，`AGENTS.md` 只留链接。
7. **空的 `LESSONS.md` 和 `docs/code-standards.md`**。`LESSONS.md` 头部写 `reviewed-through: <当前主干 sha>`。

## 3. hooks

只放**零例外**的规则，总数控制在个位数。写在项目里（Claude Code 用 `.claude/settings.json`，Codex 用它对应的机制），不改用户级设置。

- **Stop**：这一轮改过代码的，结束前跑 verify 里最快的部分（格式化、类型检查）；不过就不让结束。
- **PreToolUse**：拦截写受保护路径（真实数据目录、迁移、密钥文件）和越过单向门的命令（例如 push）。
- **提交前**：扫描密钥和本机绝对路径。

每个 hook 写好后实际触发一次，证明它生效。

## 4. 慢验证做成队列

适用于独占资源的验证：宿主软件、硬件设备、GPU、付费接口。

- 候选进队，开 N 个隔离的工位，空出一个就领下一个。每次都在独立的临时目录里跑副本。
- **N 靠实测定**：先串行跑一组作为基线，再试 2、4、8 个并行。并行结果和串行**逐字段一致**才算可用；取吞吐不再明显上升、也没有出现新故障的最小 N。
- 进程在退出时崩溃，但报告已经写完、校验也通过了：自动重跑一次，重跑通过才算通过。崩溃次数写进每日摘要。
- 不接管用户正在用的实例。开跑前确认没有冲突，必要时用独立的配置或 profile。
- 单项超过 15 分钟的检查，先给它加一个快速模式（只查关键项、不逐行写日志），不要直接塞进队列。

## 5. CI

- 有远程：主干上跑 verify:full，只在绿的提交上打 tag 或发版。
- 没有远程：每晚复盘时跑一次 verify:full 代替。

## 6. 完成标准

- [ ] 在干净的 checkout 上 verify 通过；亲手改坏一处，verify 变红
- [ ] 每个 hook 实际触发过一次
- [ ] `AGENTS.md` 写了 verify 命令、北极星口径和信任等级
- [ ] 汇报里告诉用户：现在哪些事机器能自己证明，哪些还要人看

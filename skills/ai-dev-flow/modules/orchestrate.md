# 自动推进

用户说"继续推进""自动推进"，或项目 `AGENTS.md` 已授权自动推进时使用。目标：用户不用点、不用盯，一项接一项做下去，只在第 4 节的情况找用户。

## 1. 前提

- 项目是 Git 仓库，主分支干净。没有 Git 时，先问用户要不要初始化，说明好处是能并行、能回滚。初始化时：
  - 只在本地，不加远程，除非用户另外授权。
  - 需要逐字节保留的文件（证据、样例输出）用 `.gitattributes` 写 `* -text`，避免换行转换改变散列。
- 项目 `AGENTS.md` 写明是否授权"核对通过后自动合并"。没有授权的，合并前按 `ship.md` 问用户。
- 有推进清单（计划或看板），且下一项的方向已经定了。方向没定的，先按总览第 2 节问。

## 2. 派活

- 用后台子 agent 加 worktree 隔离（Agent 工具：`isolation: "worktree"`，后台运行），任何轮次都能派，不用用户点击。
- 不用"开新会话"的方式派日常任务。原因是桌面应用规定，由通知触发的轮次只能提议会话卡片，要用户点了才开。只有用户希望在侧边栏看到过程时才开会话，而且要在用户本人发消息的那一轮一次开好。
- 子 agent 的 worktree 默认从仓库默认分支开出，见 Claude Code 设置 `worktree.baseRef`。
- Codex 执行时，用它原生的子 agent 或并行机制，每个任务各自一个 worktree。原则与本节相同。
- 派活说明要自包含，写清楚：
  - 目标、先读哪些文件、完成标准；
  - 要跑的验证；
  - 边界：不 push、不合并、不改哪些共享文件，以及项目的其他禁止项；
  - 失败产物照常保留并提交；
  - 结束报告的格式：三行汇报，加上需要总览同步的内容。
- 最多同时 2 个。会改同一批核心文件的任务不并行。
- 看板、交接入口、推进计划、决策记录这些共享文档只由你维护。子 agent 把要同步的内容写进结束报告。

## 3. 接力

子 agent 完成的通知到了以后，按顺序做：

1. **核对**：读结束报告，再按项目规定亲自核证据，比如检查点、核验报告、回归对比。结束报告是自述，不算证据。
2. **审查**：对分支的 diff 发起独立审查，见 `review.md`。子 agent 一般不能再派审查方，所以审查由你发起。有效意见交回原子 agent 修（发消息续上它的上下文），修完复跑受影响的验证。
3. **合并**：按 `ship.md` 做合并前检查。项目授权了自动合并的就直接合并，否则问用户。共享文档的冲突由你合并；业务代码冲突执行 `git merge --abort`，然后找用户。
4. **收尾**：
   - 合并后复跑验证；
   - 更新看板、计划、决策记录；
   - 项目有检查点的，生成新的检查点；
   - 已合并的子 agent worktree 交给 Claude Code 定期清理。删分支、删 worktree 仍要用户授权。
5. **汇报**：按总览第 5 节写三行，不等用户回复。
6. **派下一项**：清单里方向已定的下一项直接派。

## 4. 必须停下找用户

总览第 2 节的情况，加上：

- 被平台安全审查拦截。被拦的内容不得换写法、拆分或换个子 agent 重做。
- 同一项核对不通过，重派 2 次仍失败。
- 需要超出授权的动作：push、发布、购买、外传、安装软件、修改安全设置。

## 5. 记录

每一项在 TASK 里记：分支、`base..HEAD`、核对结果、审查方（模型、推理强度）、审查结论和处理、合并 commit。

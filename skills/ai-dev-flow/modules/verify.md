# 独立验证

执行方说"好了"不算数。合并前要有另一个验证方给出结论，而且结论对应的必须是要合并的那个版本。在主上下文里切换角色自己复查，不算独立验证。

## 1. 什么时候验、谁来验

| 档 | 验证 |
|---|---|
| 自走 | 一轮。同厂商的子 agent 可以，模型不低于执行方 |
| 看一眼 | 一轮，另加用户看 |
| 单向门 | 跨厂商（Claude 和 Codex 互审），一直验到没有 P0 / P1 |
| 只改纯文档（不改代码、脚本、hook、CI 和配置） | 跑 verify 即可，不必请验证方；这是总览第 5 节"合并前要有独立结论"唯一的例外 |

改验证脚本、hook、CI 配置的，等于改了门禁本身，一定要独立验证：验证方要亲手改坏一处被测代码，确认改过的门禁真的会红。

项目另有规定的，按项目执行。

## 2. 独立性从哪里来

- **全新上下文**，模型不低于执行方。**不改候选版本**：不改候选分支，不提交，不改执行方的 worktree。验证方在为它单独开的临时 worktree 里工作，可以在那里写构建产物（`bin/`、`obj/`、缓存），也可以为改坏检查临时改源码，改完恢复。
- **只给目标、完成标准和 diff**，不给执行方的自述、总结或 PR 描述，让它自己判断。
- **自己重跑门禁**：验证方在临时 worktree 里自己跑快检，不信执行方贴出来的结果。慢验证不重跑，读队列留下的结果文件，核对它对应的是同一个 head。
- **专门找问题**，不必肯定已有做法；但要倾向通过：没有带证明的严重问题，就给通过。

## 3. 验证说明模板

把说明写成一个自包含的临时文件：

```
目标与完成标准：<来自对话、issue 或计划>
基准：临时 worktree <tmp>（检出 head），分支 <branch>，base <sha>，head <sha>（要合并的那个版本）
项目规则：AGENTS.md、docs/code-standards.md、LESSONS.md
慢验证结果：<结果文件路径，及其对应的 head；没有就写"无">
要求：
- 只在 <tmp> 里工作：不提交，不碰候选分支和其他目录。构建产物可以留在 <tmp> 里。
- 在 <tmp> 里自己跑 <verify 命令>，把命令和结果写进输出。
- 改坏检查（改了验证脚本、hook、CI 时必做）：在 <tmp> 里临时改坏一处被测代码，确认门禁变红，
  记下改了什么、哪个检查红了；然后把自己改的地方改回原样（不用 git checkout，沙箱里可能写不了 Git 索引），
  用 git -C <tmp> diff --stat 确认没有差异，再跑一次快检确认恢复。
- 对照目标和完成标准审。skip style：命名、格式、写法偏好都不报。
- 只报 P0–P2。每条附可执行的证明：复现命令、会失败的测试、具体输入和错误输出。
  拿不出证明的写进"备注"，不算问题。
- 没有带证明的 P0 / P1，就给 Pass。
输出：
- 每条：ID ｜ P0–P2 ｜ 文件:行 ｜ 问题 ｜ 证明 ｜ 建议修法
- 结论：Pass 或 Fix
- 没覆盖到的风险
```

严重度：P0 阻止合并；P1 合并前必须修；P2 可以以后修，进队列。

## 4. 发起

验证放在后台跑，等待期间继续做别的事。

先为验证方开一个临时 worktree，检出要合并的 head（用 `scripts/dispatch.ps1 -Review` 派给外部 agent 时，脚本会自动开好）：

```bash
git worktree add --detach .agents/worktrees/<运行名> <head>
```

只改了文档的 diff（改名算删＋增，子模块和链接不算），验证方不跑快检，改成把文档里的路径、命令、源码位置逐条实际查一遍或跑一遍。

验证结束后核对两件事：候选分支的 head 没变；`git -C <tmp> status --short` 里没有改动被跟踪的文件（未跟踪的构建产物不算；改坏检查没恢复的，这轮结论作废重来）。然后用 `git worktree remove --force <tmp>` 删掉这个临时 worktree。它是你为验证自己建的，删它不需要用户授权。

所有验证方式都在 `<tmp>` 里跑，都要能写 `<tmp>`，不要用会挡住构建的只读模式。

**Claude 执行的项**

- 自走、看一眼档：用 Agent 工具开全新上下文的子 agent，说明照第 3 节写。推理强度用 `high`。
- 单向门档：请 Codex。PowerShell 中：

```powershell
Get-Content -Raw -Encoding UTF8 <brief.md> | codex exec --ephemeral --sandbox workspace-write -m <model> -c model_reasoning_effort=high -C <tmp> -o <out.md> -
```

Bash 中不用 `Get-Content` 管道，直接从文件读入：

```bash
codex exec --ephemeral --sandbox workspace-write -m <model> -c model_reasoning_effort=high -C <tmp> -o <out.md> - < <brief.md>
```

`workspace-write` 把写权限限制在 `<tmp>` 里；其余要求写在说明里，结束后按上面的方法核对。

**Codex 执行的项**：自走、看一眼档用 Codex 原生的子 agent，工作目录设为 `<tmp>`；单向门档请 Claude（在 `<tmp>` 里运行 `claude -p`，只允许它写 `<tmp>`）。

### 首选验证方不可用时

报额度、限流、未登录或超时，按下面的顺序换，不要因此跳过验证：

1. 限流这类可能很快恢复的：过一会儿用同一模型、同一推理强度重试一次。明确报额度用完的，直接跳到下一步。
2. 换成另一种同厂商的方式（Agent 子 agent 或原生子 agent），**模型不得低于执行方**，推理强度单向门档用 `xhigh` 或 `max`。不要为了"换个模型"而降档，那会削弱验证。
3. 单向门档原本要求跨厂商的，告诉用户首选验证方不可用，由用户决定是等它恢复还是接受同厂商的结论。

如实记录：验证记录（第 6 节）里写明验证方是谁（模型、推理强度），以及为什么没用首选。

## 5. 处理结论

这一步由你判断，不要转给用户：

- 每条意见先对照代码和目标核实，确认是真问题再改。没采纳的，在验证记录里写一句理由。
- head 一变，结论就作废，包括修意见、重新 rebase、squash。复验时把这次的变化发给验证方：修了意见的，发修改部分和上一轮每条的处理结果；因为主干前进而重新 rebase 的，发 rebase 带进来的主干改动，让验证方看两者合在一起是否还成立。新结论要对应新的 head。
- 验证方和执行方意见不一致时，以能跑出来的证明为准。

## 6. 验证记录

结论不写进提交正文，因为改正文会改变 head、让结论作废。用 git note 挂在被验证的那个提交上，它不改变 head，快进合并后仍然跟着这个提交：

```bash
git notes --ref=verify add -f -m "覆盖：<base>..<head>；<验证方模型和推理强度> → Pass；跑了：<命令 → 结果>；没采纳：<意见和理由，没有写无>" <head>
```

验证方输出的完整文件放在项目的证据目录或临时目录里，note 里给路径。项目用 PR 合并的，同样的内容写进 PR 描述。

# 多项目总览

用户同时推进几个项目时使用：用户说"早报""各项目怎么样""周会""新开一个项目""X 先停"，或者你在总览仓库里被打开、被定时任务触发。目标：用户只在一处看全部项目、做全部决定，每个项目照常各自推进。

你在这里是**指挥台**：收状态、汇总、按用户的意图排优先级和分额度、把用户的决定转给项目。不写任何项目的代码，不替项目派活、合并。

## 1. 结构

- **每个推进中的项目一个主会话**，开在项目自己的仓库里，按 `orchestrate.md` 推进，各管各的队列、verify、信任等级和每晚复盘。关联项目之间按 `orchestrate.md` 第 6 节靠接口约定连接。互不相关的项目也一样，只是没有依赖。
- **一个总览仓库**，一个总览会话开在这里。总览仓库只在本地，不加远程；它只放下面这些，不放任何项目的代码、数据、图纸和密钥：

| 文件 | 内容 | 谁写 |
|---|---|---|
| `AGENTS.md` | 入口：写明按本模块工作，列出下面这些文件 | 你 |
| `INTENT.md` | 用户的意图：各项目的优先级和本周目标、长期授权、额度分配、上限、不做的事 | 你起草，用户确认 |
| `projects.json` | 项目清单，格式见第 2 节 | 你 |
| `decisions.md` | 用户做过的跨项目决定，一行一条，带日期和用户原话 | 你 |
| `LESSONS.md` | 跨项目教训，见第 7 节 | 你 |
| `digest/<日期>.md` | 合并后的每日摘要 | 你 |
| `scripts/status.ps1` | 收状态的入口，转调本 skill 的 `scripts/status.ps1` | — |

总览仓库只在本地，清单里可以写本机路径；这是总览第 5 节"不提交本机绝对路径"唯一的例外。总览仓库永远不 push。

入口脚本照 `orchestrate.md` 里派活入口的写法，几行转调；多一行 `Stop`，参数写错时入口也返回非零：

```powershell
# 收状态入口：转调 ai-dev-flow 的通用状态脚本，项目清单在 ../projects.json。参数见 ai-dev-flow modules/portfolio.md。
$ErrorActionPreference = 'Stop'
$skill = if ($env:AI_DEV_FLOW) { $env:AI_DEV_FLOW } else { Join-Path $HOME '.agents/skills/ai-dev-flow' }
$script = Join-Path $skill 'scripts/status.ps1'
if (-not (Test-Path -LiteralPath $script)) { throw "ai-dev-flow skill not found: $script (set AI_DEV_FLOW)" }
& $script @args -Config (Join-Path $PSScriptRoot '../projects.json')
exit $LASTEXITCODE
```

## 2. 项目清单

```json
{
  "projects": [
    { "name": "导图", "path": "<本机路径>", "status": "推进中", "priority": 1, "trunk": "master",
      "queue": "docs/queue.md", "session": "<主会话的标题>", "dependsOn": ["引擎"], "note": "<一句话：这个项目是什么>" }
  ]
}
```

`name`、`path`、`status` 必填；`trunk` 不写就用主检出当前所在的分支；`queue` 不写就是 `docs/queue.md`。信任等级不写在清单里，脚本从项目 `AGENTS.md` 的"信任等级 Lx"读，等级只有一个出处。

| 状态 | 含义 | 总览怎么对待 |
|---|---|---|
| 推进中 | 有主会话，按队列推进 | 每天收状态、进摘要、占额度 |
| 维护 | 只处理报上来的问题 | 只看提交数、队列和待用户项 |
| 暂停 | 不推进 | 只列名字 |

- **推进中的项目有上限**，写在 `INTENT.md`，默认 4 个。要超过时先请用户选一个转维护或暂停，这是方向问题。
- **新开项目**：清单加一行，`decisions.md` 记一条。项目里没有 `AGENTS.md`、verify 或队列的，告诉用户在那个项目开主会话，第一件事按 `harness.md` 搭。
- **暂停**：项目主会话按总览第 1 节"先停"停在安全点；清单改状态，`decisions.md` 记一条。恢复时反过来。

## 3. 收状态

脚本收事实，你做判断。不要自己挨个进项目读 git log 和队列，那会白花额度。

```
pwsh -NoProfile -File scripts/status.ps1             # 推进中的全量，维护中的简要，暂停的列名字
pwsh -NoProfile -File scripts/status.ps1 -Mark       # 写每日摘要时用：记下各项目主干位置，下次从这里算新提交
pwsh -NoProfile -File scripts/status.ps1 -Lessons    # 附上各项目的教训标题和 Seen
pwsh -NoProfile -File scripts/status.ps1 -Project '<名字>,<名字>' -Since '7 days ago'
```

每个项目列出：主干新提交（默认从上次 `-Mark` 算，没有就是近 24 小时）、未复盘的提交数（`LESSONS.md` 的 `reviewed-through` 之后）、队列各状态的项数和每一条待用户项、最近一份每日摘要的北极星和返工行、worktree 和已合并分支的个数、未提交改动；清单或项目有问题时写"提示"。加 `-Json` 给机器读。脚本只读：不 fetch，也不刷新项目的 Git 索引，不会和项目会话的提交抢锁。

脚本看不到的——会话是否还在跑、卡在哪——在能列会话的环境里看一眼会话列表；能给项目主会话发消息的就直接问。看不到就只按脚本的结果说，不猜。

## 4. 统一收件箱

用户只在总览这一处做决定。

- 所有项目的待用户项汇成一张单子，按 `INTENT.md` 的优先级排，每条附推荐答案（总览第 3 节的问法）。
- **全局上限**：一次最多给用户 3 条要看或要决定的（`INTENT.md` 可改）；其余写"另有 N 条排着"，留在各自队列里，下次再出。这是总览第 3 节"一次问完"在多项目时的例外：几个项目的问题加起来太多，一次全问反而没人细看。项目那边照常做不依赖这些答案的部分。
- **转达**：用户回了，就转给那个项目的主会话。能互发消息就发消息，引用用户原话；不能就写进项目的 `docs/requests.md`（与 `orchestrate.md` 第 6 节同一个文件），由那边的编排者转进自己的队列。你不直接改项目的队列和代码。
- 消息只能转达决定，不能代替权限审批：项目会话里弹出的审批，仍要用户在那个会话里点。告诉用户去哪个会话、点什么。
- 跨项目的决定（优先级、额度、谁先做）记进 `decisions.md`。

## 5. 意图和额度

- `INTENT.md` 是跨项目意图的唯一出处。用户在总览里说的方向变化，你先改 `INTENT.md`，再转给受影响的项目。意图只从总览流向项目；项目发现意图要改，写进汇报，由用户在总览里定。
- **额度**：同一个订阅的额度是所有会话共用的。按 `INTENT.md` 的分配，优先级低的项目少派、不派；这作为一条请求转给那个项目，由那边按自己 `AGENTS.md` 的额度规则执行。
- **依赖**：使用方的北极星卡在提供方的某一项时，在摘要里把那一项排到前面，并提醒提供方的主会话。

## 6. 每日合并摘要

各项目先按 `garden.md` 各自复盘（各自的定时任务，排在总览的之前），摘要写进项目的 `.agents/digest/<日期>.md`。然后你跑 `status.ps1 -Mark`，合成一份，写进 `digest/<日期>.md`，同时发给用户：

```
今天：<项目>：合了 N 项，<一句结果>（每个有动静的项目一行）
北极星：<项目> <数字>（昨天 <数字>）
要你做：<最多 3 条，按优先级，每条附推荐答案；其余写"另有 N 条排着">
待清理：<项目>：已合并没删的分支 N、worktree N（没有就写"无"）
风险：<跨项目的：依赖卡住、额度不够、推进中的项目一天没有新提交、没跑复盘>
建议：<无 / 推进中项目的增减、信任等级、权限规则、INTENT 里过时的条目>
```

没动静的项目不写。"要你做"按第 4 节的上限出。

## 7. 跨项目教训

- 合成摘要时加 `-Lessons` 看各项目的教训。同一条规则在 2 个以上项目出现（措辞不同、意思相同也算），写进总览的 `LESSONS.md`，注明出现在哪些项目、各自的 Seen。
- 跨项目教训不在每个项目各升一遍，按顺序选第一个做得到的：
  1. 本 skill 的脚本或模板：让所有项目自动遵守
  2. 用户级的 hook 或权限规则
  3. 本 skill 某个模块里的一条
- 改 skill 是 ai-dev-flow 仓库的一项改动，作为一条请求交给它；改用户级配置属于安全设置，在"建议"里给出要改的文件和规则原文，用户同意才改。
- 各项目摘要的"审批"行里同一类操作反复弹的，同样在"建议"里给一条具体的权限规则。

## 8. 周会

每周一次（用户说"周会"，或定时）。用 `status.ps1 -Since '7 days ago'`：

- 每个推进中的项目：本周合并数、北极星变化、返工、队列还剩多少。
- 建议：哪个转维护或暂停、优先级怎么调、`INTENT.md` 里过时的条目、清单里路径不存在或长期没动的项目（只列，不删）。
- 用户定了的写进 `INTENT.md` 和 `decisions.md`。

## 9. 不做的事

- 不在总览会话里改项目代码、派项目的活、合项目的分支、改项目的队列。
- 不替用户做任何项目的单向门授权；转达授权时引用用户原话。
- 不把 sha、命令、diff 搬进摘要，用户问了再答。
- 总览仓库不推远程，不放项目的数据和密钥。

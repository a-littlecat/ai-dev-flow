# /next：一项一会话

这个会话只负责一项。进度存在队列和提交里，不存在会话里，所以换账号、换新会话都能接着做。怎么做、怎么证明、怎么验证和合并，照 ai-dev-flow skill（`$env:AI_DEV_FLOW`，默认 `~/.agents/skills/ai-dev-flow`）；这里只规定一个会话从开始到结束的步骤。

## 1. 读

1. 项目 `AGENTS.md`、队列（默认 `docs/queue.md`，`AGENTS.md` 另有写法的以它为准）、`docs/requests.md`。
2. 项目没有 `AGENTS.md`、verify 或队列的，这次的一项就是按 ai-dev-flow 的 `modules/harness.md` 把它们搭起来。
3. `docs/requests.md` 里状态是"待转"的，先转进队列，并把状态改成"已转（队列 #编号）"。这一步不算领项。
4. 项目 `LESSONS.md` 的 `reviewed-through` 之后已有 20 个以上提交，或者已经过了 7 天：这次的一项就是复盘（`modules/garden.md` 第 2 节），用户点名了别的项时除外。

## 2. 记下答复

参数里带了答复（`#7 按你的`、`#3 选 B`、`可以`、`不对，……`）时：

- 编号是队列里的 `#`。只有一项"待用户"时可以不写编号；对不上是哪一项就先问，不猜。
- 把用户原话写进那一项：
  - 方向或授权：状态改回"待做"；
  - 看一眼档回了"可以"：直接按 `land.md` 合并；
  - "不对"：按 `modules/diagnose.md` 处理。
- 答复影响别的项目（优先级、接口、额度）时，在汇报的"要你做"里写一句，周会时记进总览。

## 3. 领一项

按这个顺序选第一个：

1. `/next #n` 点名的那一项；
2. 刚刚得到答复的那一项；
3. "待做"里依赖已满足的项，按队列顺序。接力记录写着"停在安全点"的排在前面。

领到后马上把状态改成 `在做（<YYYY-MM-DD HH:mm> 起）`，单独提交队列（`queue: claim #n`）。提交前发现别的会话已经把它改成"在做"，就换下一项。"在做"的项只在用户点名时接手，接手前先读它的接力记录和分支。

没有能领的：用三行汇报说明原因（都在等你 / 都在等依赖 / 队列空了），发通知，结束。

## 4. 做

- 按 ai-dev-flow 定档（`SKILL.md` 第 2 节），然后照 `modules/build.md` 做和证明，照 `verify.md` 发起独立验证，照 `land.md` 按项目的信任等级合并。单向门和看一眼档照常停下等用户。
- 派给外部 agent（`scripts/dispatch.ps1`）或后台子 agent 的活，**在这个会话里等它结束**：`-Wait` 放进后台任务，等它的完成通知；手上没别的事就前台等。派出去的活还在跑，就不结束回合。
- 一个会话只做这一项。中途发现的新问题写进队列，不顺手做。
- 预计一个会话做不完的，拆成几项写进队列，这次只做第一项。

## 5. 收尾：每次结束回合前都做

做完、卡住、等用户、额度快用完、用户说"先停"，都按这一节收尾：

1. **队列**：把这一项改成下面三种之一，单独提交：
   - `完成（<一句结果>）`；
   - `待用户（<要用户看什么或定什么，附推荐答案和一句理由>）`；
   - `待做（接力：停在安全点 <时间>。做到哪；下一步；试过不行的路线；分支和 worktree）`。
2. **汇报**：三行，格式见 ai-dev-flow `SKILL.md` 第 6 节。
3. **通知**：
   ```
   pwsh -NoProfile -File <skill>/scripts/notify.ps1 -Title '<项目> #<n>' -Body '<结果一句>' -Level <done|user|stuck>
   ```
   做完或合并了用 `done`；要用户看或定用 `user`；卡住、停在安全点用 `stuck`。只有通知发不出去时才在汇报里提一句。

额度快用完时，先做完这一节再停。

## 6. 变体

- **`/next 连做`**：一项收尾后，队列里还有可领的自走项，就接着领下一项，最多做 3 项。遇到待用户、卡住或单向门就停。
- **`/next 收云端`**（有远程的项目）：先 `git fetch`。远程上还没合并、从云端会话推上来的分支，逐个当作它对应那一项的候选版本处理：在本地按最终版本复跑 verify，做独立验证，按信任等级合并，再按项目 `AGENTS.md` 的规定推送，最后更新队列。

## 7. 在云端会话里

云端会话没有用户级 skill。用户在那里会写"按 `skills/next/SKILL.md` 做 #n"。照本文件做，但有几点不同：

- 不改主干上的队列，也不合并，只把分支推上去，分支名里带上编号（如 `next/7-<主题>`）；
- 提交正文照 `land.md` 写，接力和结果也写在提交正文里；
- 云端发不了本机通知，跳过第 5 节第 3 步。

回到本地后，用 `/next 收云端` 合并并更新队列。

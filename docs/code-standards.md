# 代码标准

验证方逐条按这里查（`skills/ai-dev-flow/modules/verify.md` 第 3 节的"项目规则"）。条目来自复盘升级（`skills/ai-dev-flow/modules/garden.md` 第 2 节第 5 步），每条写原因和证据。

## 1. 从人写的文字里猜含义，猜错时只能影响标记，或按严的一边算

脚本读队列状态、note、决定卡这类人写的文字，靠关键词判断意思时：

- 判断的结果只能用来加标记、加提示，不能把一项藏掉、跳过或放行；
- 非要用来决定放行、归类或删除的，拿不准时按严的一边算（当作没跑、没完成、还在问用户），并在输出里说明是猜的；
- 每个关键词规则都有反例测试：同一个词出现在否定、疑问、括号里的追问（如"没有推荐""待验证""要不要"）时不能判对。

原因：这类判断错过三次，每次都让该拦的放了过去或该给用户看的被藏掉。

证据：

- `status.ps1` 按关键词判"像搁置"，把真在问用户的项藏掉了，审查两轮才改成只标记、不隐藏（d5e46ca、43c5b9a、33fc458）；
- `land-check.ps1` 读 note 里的"没跑"，半角冒号、"→ 0 passed, 3 failed"、连着两层沿用都判错过，放行了没补跑的检查（1fefb02、f4380df、2aa22f3）；
- 状态别名词后面跟着空格或"待验证""要不要"也被归成标准状态（ec53990 的 S1）；
- "没有推荐""暂无推荐方案"被当成有推荐，状态页给出"按你的"（1a00012）。

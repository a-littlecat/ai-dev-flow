# 收尾沉淀与交接

每完成一个任务，都应该让下一个任务更容易一些。只沉淀以后还会用到的东西。这一步由你自己完成，不需要问用户；只在汇报里提一句"记下了什么"。

## 1. 值得留下的

| 内容 | 放哪里 |
|---|---|
| 解决过的疑难问题（现象 → 根因 → 解法 → 怎么验证） | 项目 `docs/solutions/<主题>.md`，一个问题一个文件 |
| 以后每次都要遵守的约束 | 项目 `AGENTS.md`，写成一条，附上原因 |
| 可以自动检查的约束 | 写成脚本、测试或 hook，不写成文字 |
| 某一类工作的专门知识（宿主软件的坑、设计规范） | 对应的 skill |
| 重大的方向或架构决策 | 项目决策记录（如 `docs/DECISIONS.md`） |

写之前先搜一下有没有现成的条目。有就更新，不要重复写。

## 2. 不留的

- 聊天全文
- 一次性的状态
- 没验证过的猜测
- 密钥和账号
- 本机绝对路径
- TASK 里已经写过的内容

## 3. 交接

只在需要跨会话继续时写，写在 TASK 末尾，几行就够：

- 现在到哪了：分支、HEAD、哪些完成标准已经满足
- 下一步做什么
- 试过但行不通的路线，免得下次重复
- 下一个会话先读哪些文件

## 4. 规则本身的维护

如果发现某条规则拖慢了工作，却从来没防住过问题；或者两处规则互相矛盾：在汇报里提一句删改建议，由用户决定。

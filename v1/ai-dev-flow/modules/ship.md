# 合并落地

用户说"通过了"或"可以合并"时使用。合并的授权方式以项目规定为准。

## 1. 合并前检查

任何一项不满足，就停下来，按总览第 2 节找用户：

- TASK 里有验证证据，审查没有留下未处理的严重问题（P0 / P1）
- 用户已经明确授权合并：说了"验收通过"或"可以合并"。不需要业务验收的任务也一样，要在汇报的"要你做"里请用户说一句"可以合并"
- 主项目工作区是干净的：`git status --short`
- 没有冲突：`git merge-tree --write-tree <主分支> <任务分支>`
- `git diff --check <base>..<任务分支>` 通过
- diff 里只有本任务的文件

## 2. 合并

```powershell
git merge --no-ff <任务分支> -m "Merge <TASK-ID>: <一句话结果>"
```

如果出现冲突，执行 `git merge --abort` 退回，并报告给用户。不要自己去解决业务上的冲突。

## 3. 合并后

- 复跑项目规定的合并后验证（构建加相关测试）。失败了就报告，不要直接在主线上修。
- 更新 TASK：状态改为 `Done`，记录合并 commit 和复跑结果。
- 同步看板上对应的那一行。
- 其他仍在进行的 worktree：提醒它们同步主线，或在各自的 TASK 里写一句暂不同步的原因。

## 4. 需要用户另外授权的

push、删除分支或 worktree、打 tag、发布，每一项都要用户另外授权。合并完成后，在汇报的"要你做"里一行列出这些可选动作，等用户发话。
